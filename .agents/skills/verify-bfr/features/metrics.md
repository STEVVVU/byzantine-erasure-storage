# Reproducible service measurements

Run `python scripts/benchmark.py --run-id <fresh-id>` on isolated Ubuntu with the hash-locked runtime. Use `--smoke` only for short correctness validation, never published performance claims.

The maintained driver reuses Launch, Doctor and owned-process Cleanup. It uses four real disk-backed servers and the real CLI. Frozen input bytes follow `(i * 37 + 11) % 251`. Sizes are 4 KiB, 128 KiB and the supported 1 MiB limit. Five alternating runs compare a warm signed/quorum HTTP read with a trusted local disk read using the same Tahoe n4/k2 codec. The latter omits security and networking and is an overhead floor, not an equivalent storage system. Each side starts a fresh Python process and writes reconstructed output with fsync.

Concurrency 1/4/8 and scheduled arrivals at 4 times concurrency per second include queue delay in tails. Full cells offer `max(32, int(rate * 10))` operations, while smoke retains two. Healthy, one stopped server and two stopped servers distinguish useful completions from expected quorum rejection. A two-server failure counts as expected only when the CLI reports the specific missing metadata quorum, exits2 and creates no output; unrelated CLI failures remain errors. Completed, rejected and erroneous requests have separate latency distributions with actual sample counts in `latency_by_outcome`; raw records remain intact. A timed-out operation remains an error and is separately counted as a timeout. Empirical p99 is omitted when an outcome has fewer than100 observations; even larger bounded cells do not establish a stable production p99. Every completion verifies exact source bytes. Sixty seconds of closed-loop stability is separate from the scheduled-arrival sweep. Restart readiness, repair, storage bytes and a separate cProfile client read are retained. The server logs and raw samples survive cleanup. Read `environment.json`, `samples.json`, `summary.json` and the profile before making a claim. Never infer formal security, WAN performance or Tahoe grid performance from these loopback measurements.
